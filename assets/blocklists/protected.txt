# Domaines protégés : jamais bloqués, quelle que soit la liste.
# Toute entrée qui bloquerait l'un d'eux est retirée, à la génération
# (tools/blocklists/update_lists.py) comme à la mise à jour sur le téléphone
# (BlocklistUpdater.kt). Exemple : « docs.google.com » apparaît dans des
# listes d'hameçonnage parce que des pirates y hébergent de faux formulaires,
# mais le bloquer casserait Google Docs pour tout le monde.
#
# Une ligne protège CE nom précis. « github.io » interdit « *.github.io »
# (qui bloquerait tous les sites GitHub Pages) mais laisse passer une entrée
# exacte comme « faux-site.github.io ».

# Infrastructure partagée de grands acteurs. Ces noms ont été listés comme
# hameçonnage parce que des pirates s'en servent (une page piégée derrière
# un chemin, une redirection), mais le DNS ne voit que le nom, pas le chemin :
# bloquer le nom casse le service pour tout le monde.
# - Cache AMP de Google : les pages d'actualité « rapides » viennent de là.
cdn.ampproject.org
# - Stockage Firebase : images et fichiers de très nombreuses applications.
firebasestorage.googleapis.com
# - Téléchargements Google Cloud Storage (liens partagés).
storage.cloud.google.com
# - Redirecteur des liens sortants d'Instagram : sans lui, aucun lien d'une
#   bio ou d'un message Instagram ne s'ouvre. Instagram vérifie lui-même la
#   destination avant de rediriger.
l.instagram.com
# - Liens courts bit.ly : utilisés par des arnaques, mais surtout par des
#   millions de liens normaux (banques, opérateurs, publicités). L'analyse
#   des SMS signale déjà tout lien raccourci comme suspect.
bit.ly
